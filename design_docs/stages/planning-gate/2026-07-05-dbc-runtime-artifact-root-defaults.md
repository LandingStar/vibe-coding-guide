# DBC Runtime Artifact Root Defaults

## Status

Completed.

## Context

The project has accumulated many generated artifacts under `.codex/`, including
runtime logs, scheduler state, orchestration exchange stores, progress graph
artifacts, scratch paths, and agent output files.

That layout overstates the relationship with Codex. Codex still owns its host
registration and recovery surfaces, but DBC-owned runtime products should not
require a Codex namespace.

## Decision

DBC-owned generated artifacts default to `.dbc/`.

`.codex/` remains valid for Codex host and recovery surfaces, including:

- `.codex/config.toml`;
- Codex checkpoints and handoffs where they are explicitly recovery/handoff
  surfaces;
- Codex-host installation or trust metadata;
- historical compatibility reads.

DBC-owned generated products default to `.dbc/`, including:

- runtime invocation logs and ledgers;
- scheduler state, event logs, evidence, and reports;
- orchestration ExchangeArtifact stores and admission ledgers;
- progress graph projections and Local Work Trajectory artifacts;
- decision logs;
- scratch and agent-output files;
- agent-private folders when owned by DBC runtime policy.

## Scope

- Change program defaults for DBC-owned runtime/generated artifacts from
  `.codex/...` to `.dbc/...`.
- Keep explicit caller-provided paths authoritative, including explicit legacy
  `.codex/...` paths.
- Add legacy read fallback where practical for UI/progress graph read paths,
  especially Local Work Trajectory and scheduler trajectory projections.
- Document the `.codex` host registration versus `.dbc` runtime artifact split.
- Do not migrate the current development workspace runtime files in this gate.

## Non-Goals

- Do not rewrite historical planning gates only because they mention `.codex`.
- Do not move `.codex/config.toml`.
- Do not remove checkpoint/handoff recovery surfaces from `.codex`.
- Do not implement the future unified artifact/log index in this gate.
